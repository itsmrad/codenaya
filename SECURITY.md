# Security policy

## Reporting a vulnerability

Please don't report security issues in public GitHub issues, discussions or pull requests.

Report them privately through a [GitHub security advisory](https://github.com/itsmrad/codenaya/security/advisories/new) (the repository's **Security** tab, then **Report a vulnerability**). Include:

- what is affected (route, Convex function, agent tool, integration or the mobile app)
- steps to reproduce, or a proof of concept
- the impact you expect, such as data exposure, privilege escalation or secret disclosure

The maintainers will acknowledge the report, keep you updated while they investigate, and credit you in the advisory if you want. Please give us reasonable time to release a fix before disclosing anything publicly.

## Supported versions

Codenaya ships continuously from the `main` branch. Only the latest `main` (and the deployment built from it) receives security fixes; there are no maintained release branches.

## Scope

In scope:

- The web app and API routes in this repository (`src/`)
- Convex functions, authorization and ownership checks (`convex/`)
- The agent runtime and its tools, including sandbox isolation and secret handling (`src/features/conversations`, `src/features/sandbox-preview`)
- Credential storage and MCP integrations (`src/features/integrations`)
- The mobile app (`mobile/`)

Out of scope:

- Vulnerabilities in third-party services Codenaya uses (Clerk, Convex, Inngest, E2B, Blaxel, Daytona, model providers, MCP servers). Report those to the vendor.
- Code generated by the agent inside a user's own project
- Denial of service through volume, and findings that need a compromised account or device
- Reports from automated scanners with no demonstrated impact

## Handling secrets

Never include real credentials, API keys or user data in a report. If you find a leaked secret in this repository, report it privately as above so it can be rotated.
